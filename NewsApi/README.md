# NewsApi

REST API для системы управления новостями с ролевой моделью доступа.
Разработано как учебный проект на практике.

## Технологии

- C# / ASP.NET Core 10 Web API
- Entity Framework Core + SQLite / PostgreSQL (на выбор)
- Basic Authentication (без сторонних библиотек)
- Swagger / OpenAPI для документации и тестирования

## Архитектура

Проект построен по слоям, с чётким разделением ответственности:

- **Controllers** — только принимают запрос и вызывают один метод сервиса (или фасада), никакой бизнес-логики
- **Services** — вся бизнес-логика и проверка прав доступа. Сервисы работают только с репозиториями и не вызывают друг друга напрямую
- **Facades** — если сценарию нужно несколько сервисов сразу (например, новость вместе с комментариями), это делает отдельный фасад, который их совмещает
- **Repositories** — прямая работа с базой данных через Entity Framework Core
- **DTOs/Requests** — что принимает API от клиента
- **DTOs/Responses** — что API отдаёт клиенту (отдельно от Requests, без лишних полей вроде пароля)

## Как запустить

1. Открыть `NewsApi.slnx` в Visual Studio 2022 или новее
2. Выбрать провайдер базы данных в `appsettings.json` (см. раздел ниже)
3. Нажать F5 (или зелёную кнопку `https`)
4. Откроется Swagger UI по адресу `https://localhost:7237/swagger`

## База данных: SQLite или PostgreSQL

Проект поддерживает обе базы данных. Переключение происходит через параметр `DatabaseProvider` в `appsettings.json`:

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Data Source=news.db",
    "PostgresConnection": "Host=localhost;Port=5432;Database=newsapi;Username=postgres;Password=ВАШ_ПАРОЛЬ"
  },
  "DatabaseProvider": "Sqlite"
}
```

- `"DatabaseProvider": "Sqlite"` — используется локальный файл `news.db`, создаётся автоматически, ничего дополнительно устанавливать не нужно
- `"DatabaseProvider": "Postgres"` — требует установленный PostgreSQL и созданную пустую базу с именем `newsapi` (строку подключения нужно поправить под свои данные)

В обоих случаях таблицы создаются автоматически при первом запуске (миграции применяются сами), база наполняется тестовыми данными из `Data/data.sql`.

Миграции для каждого провайдера лежат в отдельных папках: `Migrations/Sqlite` и `Migrations/Postgres` — так Entity Framework Core различает их и не путает между собой.

## Тестовые пользователи

| Логин | Пароль | Роль |
|---|---|---|
| admin | admin123 | admin |
| reporter1 | report123 | reporter |
| reporter2 | report456 | reporter |
| subscriber1 | sub123 | subscriber |

Для авторизации в Swagger нажать кнопку **Authorize** и ввести логин/пароль — используется Basic Authentication.

## Роли и права доступа

- **Гость (без авторизации)** — может только просматривать новости и комментарии
- **admin** — полный доступ ко всем операциям над всеми сущностями
- **reporter** (журналист) — может создавать новости, редактировать и удалять только свои
- **subscriber** (подписчик) — может создавать комментарии, редактировать и удалять только свои

## Основные эндпоинты

> Поля `insertedBy` и `updatedBy` в ответах содержат не просто id, а короткую информацию об авторе (id, фамилия, имя, отчество) - чтобы не требовался отдельный запрос за данными пользователя.

### Авторизация
- `POST /api/auth/register` — регистрация нового пользователя (указываются ФИО, роль, username, password)

### Новости
- `GET /api/news?page=1&pageSize=10` — список новостей с пагинацией
- `GET /api/news/{id}` — новость по id
- `GET /api/news/{id}/with-comments` — новость вместе со всеми комментариями
- `POST /api/news` — создать новость (admin, reporter)
- `PUT /api/news/{id}` — редактировать новость (admin — любую, reporter — только свою)
- `DELETE /api/news/{id}` — удалить новость (admin — любую, reporter — только свою)

### Комментарии
- `GET /api/news/{newsId}/comments` — список комментариев к новости
- `POST /api/news/{newsId}/comments` — добавить комментарий (admin, subscriber)
- `PUT /api/news/{newsId}/comments/{id}` — редактировать комментарий (admin — любой, subscriber — только свой)
- `DELETE /api/news/{newsId}/comments/{id}` — удалить комментарий (admin — любой, subscriber — только свой)

## Структура проекта
NewsApi/
├── Auth/ - обработчик Basic Authentication
├── Controllers/ - приём HTTP-запросов, без бизнес-логики
├── Data/ - контексты базы данных (базовый + отдельные для SQLite и PostgreSQL), data.sql
├── DTOs/
│ ├── Requests/ - что принимает API
│ └── Responses/ - что отдаёт API
├── Entities/ - сущности базы данных (User, News, Comment)
├── Exceptions/ - свои исключения и глобальный обработчик ошибок
├── Migrations/
│ ├── Sqlite/ - миграции для SQLite
│ └── Postgres/ - миграции для PostgreSQL
├── Repositories/ - работа с базой данных
├── Services/
│ ├── Facades/ - объединение нескольких сервисов для сложных сценариев
│ └── ... - бизнес-логика, проверка прав доступа
└── Utils/ - вспомогательные классы (хеширование паролей и т.п.)

## Обработка ошибок

API возвращает стандартные коды HTTP, формируемые единым middleware на основе исключений:
- `400` — некорректные данные запроса (нарушены ограничения по длине и т.п.)
- `401` — не пройдена авторизация
- `403` — авторизация пройдена, но прав недостаточно
- `404` — запрашиваемая сущность не найдена
- `409` — конфликт (например, логин уже занят при регистрации)
