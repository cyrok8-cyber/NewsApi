# NewsApi

REST API системы управления новостями с ролевой моделью доступа, редакциями и внутренним чатом редакции.
Учебный проект, разработан на производственной технологической практике.

## Технологии

- C# / ASP.NET Core 10 Web API
- Entity Framework Core 10, СУБД SQLite или PostgreSQL (на выбор)
- Basic Authentication с хранением пользователя в сессии (без сторонних библиотек)
- Swagger / OpenAPI для документации и ручного тестирования
- xUnit, Moq, WebApplicationFactory для автоматических тестов

## Архитектура

Проект построен по слоям с чётким разделением ответственности:

- **Controllers** — принимают запрос и вызывают один метод сервиса или фасада, бизнес-логики в них нет
- **Services** — бизнес-логика и проверка прав доступа. Сервисы работают только с репозиториями и не вызывают друг друга
- **Services/Facades** — сценарии, которым нужно несколько сервисов сразу (новость вместе с комментариями)
- **Services/Censorship** — цензура сообщений чата по паттерну «Цепочка обязанностей» (Chain of Responsibility)
- **Repositories** — работа с базой данных через Entity Framework Core
- **DTOs/Requests** и **DTOs/Responses** — что API принимает и что отдаёт (без лишних полей вроде пароля)
- **Exceptions** — свои исключения и общий обработчик ошибок (middleware)

## Как запустить

1. Открыть `NewsApi.slnx` в Visual Studio 2022 или новее (нужен .NET SDK 10)
2. Выбрать СУБД в `NewsApi/appsettings.json` (см. следующий раздел)
3. Нажать F5 (профиль `https`)
4. Откроется Swagger UI: `https://localhost:7237/swagger`

При первом запуске таблицы создаются автоматически (применяются миграции), затем база наполняется
тестовыми данными из `Data/data.sql`: 2 редакции, 5 пользователей, 10 новостей, по 2 комментария
к каждой новости, список запрещённых слов и 2 сообщения в чате редакции.
Пароли из `data.sql` сразу после загрузки заменяются на хеши.

## База данных: SQLite или PostgreSQL

Переключение — параметр `DatabaseProvider` в `appsettings.json`:

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Data Source=news.db",
    "PostgresConnection": "Host=localhost;Port=5432;Database=newsapi;Username=postgres;Password=ВАШ_ПАРОЛЬ"
  },
  "DatabaseProvider": "Sqlite"
}
```

- `"Sqlite"` — используется локальный файл `news.db`, он создаётся сам, устанавливать ничего не нужно
- `"Postgres"` — нужен установленный PostgreSQL и пустая база `newsapi`; строку подключения поправить под себя

Миграции для каждой СУБД лежат отдельно: `Migrations/Sqlite` и `Migrations/Postgres`.
Новая миграция создаётся в консоли диспетчера пакетов для обоих контекстов:

```
Add-Migration ИмяМиграции -Context SqliteAppDbContext -OutputDir Migrations/Sqlite
Add-Migration ИмяМиграции -Context PostgresAppDbContext -OutputDir Migrations/Postgres
```

## Методы API

> Поля `insertedBy` и `updatedBy` в ответах содержат не id, а краткие сведения об авторе
> (id, фамилия, имя, отчество), чтобы клиенту не нужен был второй запрос.

### Регистрация, вход и выход
- `POST /api/auth/register` — регистрация: ФИО, роль (`admin`, `reporter`, `subscriber`), логин и пароль. Ответ 201
- `POST /api/auth/login` — вход: проверяет логин и пароль, запоминает пользователя в сессии
- `POST /api/auth/logout` — выход: очищает сессию (ответ 401, чтобы клиент забыл сохранённые логин и пароль)

ФИО проверяется: только русские буквы и дефис. Пароли хранятся в виде хеша PBKDF2
(SHA-256, 100 000 итераций, случайная «соль»).

### Пользователи
- `GET /api/users/{id}` — сведения о пользователе (admin)
- `POST /api/users/{id}/block` — заблокировать пользователя на `durationMinutes` минут (admin)

### Новости
- `GET /api/news?page=1&pageSize=10` — список новостей с пагинацией
- `GET /api/news/{id}` — новость по id
- `GET /api/news/{id}/with-comments` — новость вместе с комментариями
- `POST /api/news` — создать новость (admin, reporter)
- `PUT /api/news/{id}` — изменить новость (admin — любую, reporter — только свою)
- `DELETE /api/news/{id}` — удалить новость (admin — любую, reporter — только свою)

### Комментарии
- `GET /api/news/{newsId}/comments` — комментарии к новости
- `POST /api/news/{newsId}/comments` — добавить комментарий (admin, subscriber)
- `PUT /api/news/{newsId}/comments/{id}` — изменить комментарий (admin — любой, subscriber — только свой)
- `DELETE /api/news/{newsId}/comments/{id}` — удалить комментарий (admin — любой, subscriber — только свой)

### Редакции

Журналисты (reporter) объединяются в редакции и публикуют новости от их имени.
Создаёт редакции и управляет их составом только администратор. Журналист состоит
максимум в одной редакции или работает в одиночку.

В новости поле `publishedBy` содержит подпись: сначала наименование редакции, затем редактор,
например `Редакция «Городские вести», редактор: Журналистов Пётр Петрович`. У одиночки — только ФИО.
Редакция запоминается в момент публикации: если журналист позже уйдёт из редакции,
его прошлые новости останутся за редакцией.

- `GET /api/editorial-offices` — список редакций с журналистами (все)
- `GET /api/editorial-offices/{id}` — редакция по id (все)
- `POST /api/editorial-offices` — создать редакцию (admin)
- `PUT /api/editorial-offices/{id}` — изменить наименование и описание (admin)
- `DELETE /api/editorial-offices/{id}` — удалить редакцию; журналисты становятся одиночками (admin)
- `POST /api/editorial-offices/{id}/members/{userId}` — добавить журналиста в редакцию (admin)
- `DELETE /api/editorial-offices/{id}/members/{userId}` — исключить журналиста из редакции (admin)

### Чат редакции

Внутренний чат журналистов одной редакции. Писать могут только журналисты этой редакции,
администратор может читать любой чат (модерация), но не пишет в него.

- `GET /api/editorial-offices/{officeId}/chat?page=1&pageSize=50` — сообщения (журналисты редакции, admin)
- `POST /api/editorial-offices/{officeId}/chat` — отправить сообщение (журналисты редакции)

Каждое сообщение перед сохранением проходит цензуру, построенную по паттерну
**Chain of Responsibility** (папка `Services/Censorship`). Обработчики связаны в цепочку,
каждый отвечает за одно правило и передаёт сообщение следующему:

1. `EmptyMessageHandler` — пустое сообщение отклоняется (400)
2. `MaxLengthHandler` — сообщение длиннее 1000 символов отклоняется (400)
3. `CapsLockHandler` — текст, набранный капсом, переводится в обычный регистр
4. `LinkFilterHandler` — внешние ссылки заменяются на `[ссылка удалена]`
5. `BannedWordsHandler` — запрещённые слова заменяются звёздочками

Если цензура изменила текст, у сообщения `wasCensored = true`.
Новое правило добавляется одним классом-обработчиком и одной строкой в `ChatCensorshipChain`.

## Запрещённые слова и блокировки

- Новость или комментарий с запрещённым словом (таблица `BannedWords`) отклоняется с кодом 400,
  попытка записывается пользователю
- 5 попыток опубликовать текст с запрещёнными словами — блокировка на 24 часа
- 5 неудачных попыток входа подряд — блокировка на 30 минут
- Администратор может заблокировать пользователя вручную (`POST /api/users/{id}/block`)
- Заблокированный пользователь не может войти даже с верным паролем

Правила заданы в `Utils/BlockingPolicy.cs`.

## Обработка ошибок

API возвращает стандартные коды HTTP, тело ошибки — JSON вида `{ "status": 404, "message": "..." }`:

- `400` — некорректные данные запроса или запрещённое слово
- `401` — не пройдена аутентификация, пользователь заблокирован
- `403` — аутентификация пройдена, но прав недостаточно
- `404` — запрашиваемая сущность не найдена
- `409` — конфликт (логин уже занят, редакция с таким наименованием уже есть, журналист уже состоит в редакции)
