# NewsApi

REST API для системы управления новостями с ролевой моделью доступа.
Разработано как учебный проект на практике.

## Технологии

- C# / ASP.NET Core 10 Web API
- Entity Framework Core + SQLite
- Basic Authentication (без сторонних библиотек)
- Swagger / OpenAPI для документации и тестирования

## Как запустить

1. Открыть `NewsApi.slnx` в Visual Studio 2022 или новее
2. Нажать F5 
3. Откроется Swagger UI по адресу `https://localhost:7237/swagger`

База данных (`news.db`) создаётся автоматически при первом запуске и наполняется тестовыми данными из файла `Data/data.sql` (2 редакции, 5 пользователей, 10 новостей, по 2 комментария к каждой, 2 сообщения в чате редакции).

## Тестовые пользователи

| Логин | Пароль | Роль |
|---|---|---|
| admin | admin123 | admin |
| reporter1 | report123 | reporter |
| reporter2 | report456 | reporter |
| subscriber1 | sub123 | subscriber |
| reporter3 | report789 | reporter |

reporter1 и reporter3 состоят в редакции «Городские вести», reporter2 — журналист-одиночка.

Для авторизации в Swagger нажать кнопку **Authorize** и ввести логин/пароль — используется Basic Authentication.

## Роли и права доступа

- **Гость (без авторизации)** — может только просматривать новости и комментарии
- **admin** — полный доступ ко всем операциям над всеми сущностями
- **reporter** (журналист) — может создавать новости, редактировать и удалять только свои
- **subscriber** (подписчик) — может создавать комментарии, редактировать и удалять только свои

## Основные эндпоинты

> Поля `insertedBy` и `updatedBy` в ответах содержат не просто id, а короткую информацию об авторе (id, фамилия, имя, отчество) - чтобы не требовался отдельный запрос за данными пользователя.

### Авторизация
- `POST /api/auth/register` — регистрация нового пользователя (указываются ФИО, роль, username, password)

### Новости
- `GET /api/news?page=1&pageSize=10` — список новостей с пагинацией
- `GET /api/news/{id}` — новость по id
- `GET /api/news/{id}/with-comments` — новость вместе со всеми комментариями
- `POST /api/news` — создать новость (admin, reporter)
- `PUT /api/news/{id}` — редактировать новость (admin — любую, reporter — только свою)
- `DELETE /api/news/{id}` — удалить новость (admin — любую, reporter — только свою)

### Комментарии
- `GET /api/news/{newsId}/comments` — список комментариев к новости
- `POST /api/news/{newsId}/comments` — добавить комментарий (admin, subscriber)
- `PUT /api/news/{newsId}/comments/{id}` — редактировать комментарий (admin — любой, subscriber — только свой)
- `DELETE /api/news/{newsId}/comments/{id}` — удалить комментарий (admin — любой, subscriber — только свой)


### Редакции

Журналисты (reporter) могут объединяться в редакции и публиковать новости от их имени.
Создаёт редакции и управляет их составом только администратор. Журналист может состоять
максимум в одной редакции или работать в одиночку.

В новости поле `publishedBy` содержит подпись: сначала наименование редакции, затем редактор,
например `Редакция «Городские вести», редактор: Журналистов Пётр Петрович`. У одиночки — только ФИО.
Редакция запоминается в момент публикации: если журналист позже уйдёт из редакции,
его прошлые новости останутся за редакцией.

- `GET /api/editorial-offices` — список редакций с журналистами (все)
- `GET /api/editorial-offices/{id}` — редакция по id (все)
- `POST /api/editorial-offices` — создать редакцию (admin)
- `PUT /api/editorial-offices/{id}` — изменить наименование и описание (admin)
- `DELETE /api/editorial-offices/{id}` — удалить редакцию; журналисты становятся одиночками (admin)
- `POST /api/editorial-offices/{id}/members/{userId}` — добавить журналиста в редакцию (admin)
- `DELETE /api/editorial-offices/{id}/members/{userId}` — исключить журналиста из редакции (admin)

### Чат редакции

Внутренний чат для журналистов одной редакции. Писать могут только журналисты этой редакции,
администратор может читать любой чат (модерация), но не пишет в него.

- `GET /api/editorial-offices/{officeId}/chat?page=1&pageSize=50` — сообщения (журналисты редакции, admin)
- `POST /api/editorial-offices/{officeId}/chat` — отправить сообщение (журналисты редакции)

Каждое сообщение перед сохранением проходит цензуру, построенную по паттерну
**Chain of Responsibility** (папка `Services/Censorship`). Обработчики связаны в цепочку,
каждый отвечает за одно правило и передаёт сообщение следующему:

1. `EmptyMessageHandler` — пустое сообщение отклоняется (400)
2. `MaxLengthHandler` — сообщение длиннее 1000 символов отклоняется (400)
3. `CapsLockHandler` — текст, набранный капсом, переводится в обычный регистр
4. `LinkFilterHandler` — внешние ссылки заменяются на `[ссылка удалена]`
5. `BannedWordsHandler` — запрещённые слова заменяются звёздочками

Если цензура изменила текст, у сообщения `wasCensored = true`.
Новое правило добавляется одним классом-обработчиком и одной строкой в `ChatCensorshipChain`.

## Структура проекта
NewsApi/
├── Auth/ - обработчик Basic Authentication
├── Controllers/ - приём HTTP-запросов
├── Data/ - контекст базы данных, data.sql
├── DTOs/ - объекты для обмена данными с клиентом
├── Entities/ - сущности базы данных (User, News, Comment)
├── Exceptions/ - свои исключения и глобальный обработчик ошибок
├── Migrations/ - миграции Entity Framework Core
├── Repositories/ - работа с базой данных
├── Services/ - бизнес-логика, проверка прав доступа
└── Utils/ - вспомогательные классы (хеширование паролей и т.п.)

## Обработка ошибок

API возвращает стандартные коды HTTP:
- `400` — некорректные данные запроса (нарушены ограничения по длине и т.п.)
- `401` — не пройдена авторизация
- `403` — авторизация пройдена, но прав недостаточно
- `404` — запрашиваемая сущность не найдена
- `409` — конфликт (например, логин уже занят при регистрации)
