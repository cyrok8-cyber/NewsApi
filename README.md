# NewsApi

REST API для системы управления новостями с ролевой моделью доступа.
Разработано как учебный проект на практике.

## Технологии

- C# / ASP.NET Core 10 Web API
- Entity Framework Core + SQLite
- Basic Authentication (без сторонних библиотек)
- Swagger / OpenAPI для документации и тестирования

## Как запустить

1. Открыть `NewsApi.sln` в Visual Studio 2022 или новее
2. Нажать F5 
3. Откроется Swagger UI по адресу `https://localhost:7237/swagger`

База данных (`news.db`) создаётся автоматически при первом запуске и наполняется тестовыми данными из файла `Data/data.sql` (3 пользователя, 10 новостей, по 2 комментария к каждой).

## Тестовые пользователи

| Логин | Пароль | Роль |
|---|---|---|
| admin | admin123 | admin |
| reporter1 | report123 | reporter |
| reporter2 | report456 | reporter |
| subscriber1 | sub123 | subscriber |

Для авторизации в Swagger нажать кнопку **Authorize** и ввести логин/пароль — используется Basic Authentication.

## Роли и права доступа

- **Гость (без авторизации)** — может только просматривать новости и комментарии
- **admin** — полный доступ ко всем операциям над всеми сущностями
- **reporter** (журналист) — может создавать новости, редактировать и удалять только свои
- **subscriber** (подписчик) — может создавать комментарии, редактировать и удалять только свои

## Основные эндпоинты

> Поля `insertedBy` и `updatedBy` в ответах содержат не просто id, а короткую информацию об авторе (id, фамилия, имя, отчество) - чтобы не требовался отдельный запрос за данными пользователя.

### Авторизация
- `POST /api/auth/register` — регистрация нового пользователя (указываются ФИО, роль, username, password)

### Новости
- `GET /api/news?page=1&pageSize=10` — список новостей с пагинацией
- `GET /api/news/{id}` — новость по id
- `GET /api/news/{id}/with-comments` — новость вместе со всеми комментариями
- `POST /api/news` — создать новость (admin, reporter)
- `PUT /api/news/{id}` — редактировать новость (admin — любую, reporter — только свою)
- `DELETE /api/news/{id}` — удалить новость (admin — любую, reporter — только свою)

### Комментарии
- `GET /api/news/{newsId}/comments` — список комментариев к новости
- `POST /api/news/{newsId}/comments` — добавить комментарий (admin, subscriber)
- `PUT /api/news/{newsId}/comments/{id}` — редактировать комментарий (admin — любой, subscriber — только свой)
- `DELETE /api/news/{newsId}/comments/{id}` — удалить комментарий (admin — любой, subscriber — только свой)

## Структура проекта
NewsApi/
├── Auth/ - обработчик Basic Authentication
├── Controllers/ - приём HTTP-запросов
├── Data/ - контекст базы данных, data.sql
├── DTOs/ - объекты для обмена данными с клиентом
├── Entities/ - сущности базы данных (User, News, Comment)
├── Exceptions/ - свои исключения и глобальный обработчик ошибок
├── Migrations/ - миграции Entity Framework Core
├── Repositories/ - работа с базой данных
├── Services/ - бизнес-логика, проверка прав доступа
└── Utils/ - вспомогательные классы (хеширование паролей и т.п.)

## Обработка ошибок

API возвращает стандартные коды HTTP:
- `400` — некорректные данные запроса (нарушены ограничения по длине и т.п.)
- `401` — не пройдена авторизация
- `403` — авторизация пройдена, но прав недостаточно
- `404` — запрашиваемая сущность не найдена
- `409` — конфликт (например, логин уже занят при регистрации)
